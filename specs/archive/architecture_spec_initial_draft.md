# LyricNote: iTunes 洋楽和訳・ライナーノーツ付与システム 詳細仕様書 (改訂版)

## 1. プロジェクトの目的と目標（Why）

**「言葉の壁を越え、アーティストが楽曲・アルバムに込めた真のメッセージや物語を深く理解し、手持ちの洋楽ライブラリでの音楽鑑賞体験を極限まで豊かにすること」**

本ツールは単なる直訳ツールではない。プログレやロックオペラなど、アルバム全体を通したテーマ性や架空のキャラクター、ダブルミーニング・造語などを正確に読み解き、一貫した世界観を持った「和訳」と「ライナーノーツ」を生成・付与することで、ユーザーに深い音楽鑑賞の喜びを提供することを最終目標とする。

---

## 2. 絶対遵守ルール（Safety & Limits）

開発およびシステム稼働において、以下のルールを強制する。

1. **データアクセス制限**:
   - キャッシュ・バックアップ等は指定ディレクトリ（`X:\LylicData`）配下のみに制限。
2. **楽曲ファイルの保護**:
   - `track.Delete()` や `os.remove()` による音楽ファイル（`.m4a`, `.mp3`等）の物理削除・バイナリ改変を絶対禁止。メタデータ更新は iTunes COM API に委ねる。
3. **API課金リスクの排除（追加課金ゼロ）**:
   - クラウドLLM (Gemini API) の利用時は、無料枠を超過しないようRate Limitエラーを検知して停止する。
   - **手動ハイブリッドモード**: ユーザー加入済みの「AI Proプラン (Gemini Advanced)」をブラウザ経由で活用できるよう、UIに「Gemini用プロンプトのコピー＆出力結果のペースト」機能を実装し、API制限を回避する。

## 3. インフラ・アクセス設計とセキュリティ要件

### 3.1. 外部公開のセキュリティ評価と実装方針
1. **外部からのアクセス要件（外部利用ガイドライン）**:
   - 本システムは iTunes COM API に直接アクセスし、ローカルマシンのデータ（ファイルシステム・レジストリ等）を操作する権限を持つ。そのため、インターネットからの不正アクセスは重大な情報漏洩・システム破壊のリスクを伴う。
   - **Gradio Share（`--share`）のセキュリティ評価**: GradioのShare機能による公開URL（`*.gradio.live`）は、不特定多数からのアクセスを許可する。Basic認証を設定可能だが、GradioのBasic認証にはレートリミット（連続試行防止）やアカウントロック機能がなく、総当たり攻撃に対して極めて脆弱である（OWASP非推奨）。また、Gradio自体の未知の脆弱性を突かれるリスクもある。
2. **結論と実装方針（Gradio Shareの不採用）**:
   - **セキュリティリスクが許容範囲を超えているため、GradioのShare機能およびBasic認証機能の実装は「不可（却下）」とする。** アプリ内にこれらの実装を行わない。
   - サーバーは常にローカルネットワーク内（`server_name="0.0.0.0"`）のみで起動し、外部からの直接アクセスを遮断する。
3. **外部からの安全な接続方法（Tailscale等の推奨）**:
   - 外出先から本システムを利用する場合は、**Tailscale** や **ZeroTier** などのセキュアな暗号化メッシュVPN（Zero Trust Network Access）を利用することを必須ガイドラインとする。これにより、インターネットにポートを公開することなく、安全にローカルの `0.0.0.0:7860` にアクセス可能となる。

## 4. アルバム指向アーキテクチャとライブラリスキャン仕様

### 4.1. iTunesライブラリスキャン仕様と多言語対応
- **スキャン対象**:
  - 全ての音声トラック（Audioファイル）を対象に自動で一括スキャンする（ユーザーに「洋楽のみ」等の選択を求めない）。
  - ビデオ、Podcast、PDFブックレット等の非音声ファイル、および曲名・アーティスト・アルバム名が空の不正トラックは自動的にスキップする。
- **日本語楽曲（邦楽）の透過的ハンドリング**:
  - スキャンされた全楽曲に対し、パイプライン処理内で自動的に言語判定（メタデータや取得した歌詞に基づく判定）を行う。
  - **邦楽の処理**: 和訳処理（ローカルLLM）は不要なため自動でスキップするが、歌詞の取得（LRCLIB等）およびクラウドLLMを用いた「楽曲・アルバム解説（ライナーノーツ）」の生成・登録は洋楽と同様に行う。これにより、ユーザーはモードを意識することなく、ライブラリ全体の楽曲解説をシームレスに享受できる。

### 4.2. 音楽評論家（クラウドLLM / ブラウザGemini手動）
- **役割**: アルバム全体の時代背景やコンセプトの抽出に加え、各収録楽曲の個別解説を生成する。
- **ライブアルバムの特別処理**: ライブアルバム（Live等）の場合は、楽曲単位の解釈よりも、「ツアーの背景、動員数、録音場所、メンバー編成」など『ライブとしての価値』を重視した解説を生成する。
- **出力形式と適用仕様**:
  - LLMはJSON形式で `album_overview`（アルバム全体の解説）と `track_commentaries`（配列: 各曲名と個別解説）を出力する。
  - iTunesへの書き込み時、システムは対象曲のメタデータを基にJSONから個別解説を抽出し、「アルバム全体解説」＋「該当曲の個別解説」という形で統合して書き込む。これにより、全曲に一律のテキストが適用される問題を防ぎ、楽曲ごとの深い鑑賞体験を提供する。

### 4.3. 翻訳職人（ローカルLLM: gemma2:9b）と翻訳メモリ
- **役割**: 用語集(JSON)を動的プロンプトに組み込み、アルバム順に一貫した和訳を生成する（完全ローカル）。
- **翻訳メモリ機構**: 英語歌詞のハッシュを照合し、重複曲（ベスト盤等）は処理時間ゼロで過去の和訳を自動適用する。

### 4.4. データベースの保持方針（辞典化）
- SQLiteに保存された和訳やライナーノーツは削除せず永続蓄積し、UI上の「洋楽ライナーノーツ辞典」からいつでも閲覧可能とする。
